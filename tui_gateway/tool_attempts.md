# Owned attempt metadata

`tools.attempts` reads durable tool attempt metadata for an explicitly attached live session. Params require `session_id`; `limit` defaults to 50 and is an integer from 1 to 100. `before_attempt_id` optionally advances from a cursor returned by the previous page. Cursors are scoped to the same durable session and profile. There is no omitted-session settings fallback.

The gateway checks transport membership and the live session generation before and after reading the canonical profile SessionDB under home, secret and terminal scope. Missing DB/session storage reports `available: false`. Foreign, missing or replaced attachments fail with 4001. An unavailable cursor or raced page fails with 5036. No tool dispatch, inference, grant or retry is performed.

The result protocol is `hermes-tool-attempts-v1`, coverage `exact-session-metadata-only`. Pages order by creation time then attempt ID, newest first, and contain at most `limit` rows plus an optional `next_cursor`. Concurrent settlements may change state between pages; this is not a frozen cross-page snapshot. Rows retain host attempt/parent IDs, tool name, state, terminal flag, timestamps and result digest/byte count. They omit request digests, arguments, credentials and result bodies.

`pending` and `running` remain nonterminal. `returned` establishes handler return, not successful delivery, confirmed stop or complete effects. Error returns may have partial effects. Reading a record never authorizes replay. Stable client replay IDs, payload/artifact recovery and a distributed attempt ledger remain separate work.

Parent-bound code children also freeze schema fingerprints when the authorized parent starts. Published definitions are copied under the agent publication lock; eligible deferred definitions come from the same profile's existing full resolver. The child checks its selected definition before policy and again immediately before invocation, after middleware/approval waits. Same-name schema replacement or malformed definitions reject the call; a rejection after admission settles its attempt as `rejected` with no dispatched timestamp. Capturing a snapshot never republishes agent tools or rewrites conversation context. These fingerprints are private server-local identities, not the common SDK schema hash.

This schema fence does not add an external tool-only RPC or expand the code sandbox allowlist. Deployed executor attestation, broader argument/effect admission and distributed grants/budgets remain separate requirements.

Registered child tools additionally pin the profile's actual registration object, callable, synchronous/asynchronous mode and raw schema digest at parent entry. Rejection checks this identity before invocation. A host-only context binding follows the existing agent dispatch into the real registry, where selection is committed under the existing registry lock and the captured callable is invoked outside it. Same-schema registration replacement cannot redirect that invocation. Standalone registry dispatch also selects callable/mode once rather than reading mutable entry fields again after signature handling.

Replacement detected before agent invocation settles `rejected` without a dispatched timestamp. Replacement between agent invocation and registry selection produces `returned-error`; the invocation started, but the refused replacement handler did not execute. Such a record never establishes effects, delivery or confirmed stop. These are in-process registered-tool fences, not deployed executor version attestation or a generic RPC contract; agent-level inline providers still require separate revision admission.
