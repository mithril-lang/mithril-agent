# Owned tool context and selected workspace

The attached session's built schema snapshot exposes an opaque context ID and schema revision. Main/runtime identity and profile isolation are distinct from a human effect or target grant. Discovery never rebuilds a frozen conversation schema or grants execution.

Changing the session's selected `cwd` now rotates the context ID alongside agent/profile changes. Returning to the old directory produces another new ID, so an old approval cannot revive through an A → B → A change. The path stays host-side; schema revision and the wire shape stay unchanged. The owned RPC checks this context before its durable handler claim and after dispatch. A new call with a retired context is refused before an attempt row or handler effect is created. Same-ID lookup of an existing attempt remains metadata-only.

After current-context admission, the private tool-only task inherits the owning conversation's backend overrides and selected nonempty working directory. Registration updates a cached environment's current directory as well as its raw scoped override. Authority is checked again before dispatch. Relative file targets therefore use the selected workspace instead of the gateway process directory. These operations use the existing routed home, secret and terminal scopes; credentials never cross the snapshot.

The context also tracks the owner's resolved terminal configuration and parent-task overrides. Each snapshot re-enters the existing complete home/secret/terminal profile scope without hydrating external secret sources, even when called inside a scope captured before an approval wait. A bounded finite-JSON digest stays host-side; the RPC still exposes only the opaque context ID and the unchanged schema revision. No configuration, endpoint, override or policy digest is added to the wire. An observed configuration/override change rotates the context. Failed policy resolution retires it too, so repairing the policy cannot revive the old context.

Owned dispatch also binds a private runtime generation through the existing task-override registry. Agent/profile/terminal-policy changes rotate that generation; a selected-cwd-only change keeps it, allowing the same cached environment to follow the new cwd. The stable task and request/attempt digest do not change. The generation qualifies environment cache keys before ordinary container/session sharing and disables fallback to an old raw-task cache slot. File, terminal and remote-code resolution use that same qualified key. Remote code resolves the raw scoped task overrides instead of incorrectly reading overrides at the collapsed cache key. Local and remote Python kernel keys include the generation while preserving their owner/profile identity for normal teardown. Switching policy back creates another generation rather than reviving an earlier kernel namespace. Existing non-owned callers retain their previous keys.

The regressions use real file handlers and durable SessionDB: stale context creates no attempt, a fresh relative path reads the selected target, returning to the original directory does not revive old authority, and the cached environment reads the original target only under a fresh context. An on-disk terminal timeout or local-to-SSH change invalidates old authority before a new attempt. A policy change at the real guardrail/middleware boundary refuses dispatch after the durable claim, leaving a terminal rejected receipt with no dispatch timestamp; replay remains metadata-only. A second profile is unchanged, and on-disk parse refusal/repair and scoped parent overrides cannot revive approval. SSH is never started in these tests.

The runtime regression uses actual file and terminal handlers and confirms that both and the remote-code resolver share an environment within each generation, with distinct environments across policy A → B → A. Actual local Python kernels retire their old namespaces without resetting another profile. A separate factory fixture supplies a real local shell/process/file transport for SSH-selected code: local → file-RPC → changed file-RPC → local gets fresh namespaces at every generation while the other profile retains its value. This qualifies the real remote file protocol and selected factory/cache path, not SSH credentials or network. Explicit owner/profile cleanup disposes the test kernels.

This is a cwd/terminal-policy fence and owned cache-generation mechanism, not a complete effect/target manifest or proof of every backend migration. Real SSH/container/provider lifecycle and all consumers, including delegation and asynchronous effects, still require qualification. New generations do not authorize cancelling or replaying old background effects; previous generations remain under existing lifetime/cleanup policy. Non-terminal provider configuration, explicit target resolution, resource integrity, grants for all operations, public/installed qualification and filesystem scope policy remain separately required. Changes that occur and return entirely between observations are not detected. A handler return does not establish completion of every external effect; an already-dispatched effect is never retried merely because context changed.

## Desktop target preview consumer qualification

It is test input, never a runtime setting. The stdio driver compares each call's exact arguments, context/revision and target digest with its preceding host preview, while the real dispatcher, agent, file handlers and durable attempts retain their existing checks. A-to-B-to-A profile switching, lost-result replay and reconnect still exercise the existing real paths. The Desktop adapter obtains a fresh preview on its selected attached session; it refuses mismatched expected targets and retired discovery context before sending a call. Explicit null target coverage stays unknown, and preview never grants an effect.

Mounted Desktop hook tests separately cover cancellation, connection/model/provider/session replacement and unmount during preview. Profile/issuer/provider construction fixtures remain in the cross-repository qualifiers. This does not qualify real Electron/native pairing, all operations, remote/atomic filesystem targets, public or installed clients. The prior separate 300-second failure remains unresolved.
